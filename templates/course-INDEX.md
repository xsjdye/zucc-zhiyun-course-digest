## 课程综述

> 三段的流程是：**先归纳全课知识点 → 再对应专家分析 → 最后给出导出结果**。
> 攒够 **2 讲以上**再写第一版，之后每加一讲回填更新；只有 1 讲时留空，不要硬写。
>
> ⚠️ 与单讲笔记同一条规矩：**一、二段分层不合并**。第一段必须是能从各讲笔记里核对的，
> 第二段是 `persona` 视角的判断，**不得当作"课上说的"引用**。

### 一、知识点整体归纳（可回溯到讲次）

<把全课所有讲次的知识点拍平、去重、归并成一张知识地图。要求：

- 这门课一共几块知识，**彼此是什么关系**（哪块是前提、哪块是推论、哪几块并列）
- 每块挂在哪些讲次上（写 `第NN讲`，便于回溯）
- **不逐讲复述**——这是归纳，不是目录；把重复出现的概念合并，把没讲透的标出来

示例：

```
  ① <承重块>（第01–03讲）  ← 全课前提，后面都建在它上面
        ├─ ② <推论块>（第04–05讲）
        └─ ③ <并列块>（第06–08讲）
                 └─ ④ <收口块>（第09讲，回到①做闭环）
```

**讲透了 / 没讲透**：<哪些概念老师反复展开、哪些只是一句带过——后者注明"课上未展开">

### 二、对应专家分析（`persona` 视角，非本课内容）

> 这一段是 *<persona>* 视角的判断，不是老师讲的。引用时不要写成"课上说的"。

按这个视角回答四件事：

1. **这套知识在行业里处在什么位置**——是主干、是入门、还是某一派的说法？同行更常用什么替代框架？
2. **哪些能直接用，哪些要打折**——课上给的哪些做法在今天仍然成立，哪些是理想化/教学简化，实操里会怎么变形
3. **边界在哪**——这门课**不覆盖**什么，而这些东西恰恰是上手时才撞墙的
4. **和相邻领域的接口**——学完这套，往哪个方向接最顺（工具、岗位、进阶教材）

### 三、导出结果

| 维度 | 结论 |
|---|---|
| **学完应该会什么** | <一件能说出口的能力，不要写"了解/熟悉"> |
| **能做什么** | <具体可交付物：能做出什么、能答上什么问题> |
| **行业对得上什么** | <岗位名 / 业务场景 / 面试常问的点> |
| **还缺哪几块** | <要真正上手，必须自己补的部分，按优先级列> |
| **自测问题** | <3–5 个问题，答不上来说明这块没掌握> |
